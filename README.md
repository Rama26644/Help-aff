# Rama — рабочий помощник

Первая основа закрытого сайта для Altex и Buyo. Есть вход, общая база вебов, задачи с завершением, записи условий, черновики контента и отдельный раздел подключений. Интерфейс адаптирован для телефона. Это версия для разработки, ещё не размещённый публичный сайт.

## Запуск на Mac

1. Установите Node.js 24 LTS.
2. Откройте папку проекта в терминале.
3. Выполните `npm ci`.
4. Скопируйте `.env.example` в `.env` командой `cp .env.example .env`.
5. В `.env` задайте свой `ADMIN_PASSWORD` (минимум 12 символов). Не отправляйте пароль в чат и не добавляйте `.env` в Git.
6. Выполните `npm run dev`. Откройте локальный адрес с портом 3000 в браузере и войдите с указанным паролем.

При первом запуске создаётся единственный пользователь rama. Публичной регистрации нет. Пароль из .env применяется только при первоначальном создании пользователя; его изменение в файле не меняет уже сохранённый пароль.

## База и проверки

Без DATABASE_URL используется PGlite — встроенный PostgreSQL-движок, сохраняющий данные в `.data/postgres`. Он подходит для одной локальной копии приложения. Не запускайте несколько экземпляров на одной папке данных.

`npm test` проверяет вход, защиту Origin, запрет доступа без сессии, разделение компаний, создание и завершение задач, восстановление базы и сессии после перезапуска, выход. `npm run build` собирает интерфейс.

Для внешнего PostgreSQL задайте DATABASE_URL. Схема создаётся при старте. В проекте нет демонстрационных записей. Интерфейс сохраняет данные только через сервер.

## Интеграции

В «Подключениях» есть Altex и Buyo и возможность добавить описание источника. Сейчас это реестр источников: адаптеры, проверка API, синхронизация и ввод ключей ещё не реализованы. Нельзя вводить секреты в название или заметку. Статистика честно показывает отсутствие подключения. Подключения будут добавляться отдельно после создания основы сайта, без ключей в коде frontend.

## Размещение с PostgreSQL

Выберите хостинг и домен. Платные ресурсы не создавались. Подготовлены Dockerfile и compose.yaml; Docker-сборка и внешний PostgreSQL в этой среде пока не проверялись.

В защищённых настройках хостинга задайте ADMIN_PASSWORD и POSTGRES_PASSWORD (для compose используйте разные стойкие буквенно-цифровые пароли). Запустите `docker compose up -d --build`. Поставьте HTTPS reverse proxy перед локальным портом 3000; не публикуйте PostgreSQL. В production cookie требует HTTPS, поэтому вход через обычный HTTP не будет работать. Приложение доверяет одному reverse proxy: не предоставляйте прямой внешний доступ к его порту. Проверка состояния: GET /api/health, без выдачи рабочих данных.

Контейнер app работает без root. База хранится в томе postgres_data. Не используйте `docker compose down -v`: это удаляет базу. Сайт на хостинге не зависит от включённого Mac, но фактическое размещение ещё не выполнено.

## Резервные копии

Для локальной версии остановите приложение, скопируйте целиком `.data/postgres` в защищённое место, затем запустите приложение. Для восстановления остановите приложение и замените папку данных копией. Копия содержит рабочие данные и хеш пароля — храните её закрытой.

Для compose: `docker compose exec -T db pg_dump -U rama -d rama > backup.sql`. Настройте ежедневные копии средствами хостинга, шифрование и ограниченный доступ. Восстановление в пустую подготовленную БД: `docker compose exec -T db psql -U rama -d rama < backup.sql`. Команды контейнерного восстановления пока не проверялись в этой среде.

## Ограничения первой версии

Условия и контент пока сохраняются как записи: нет истории изменений условий, публикации и планировщика. Карточки вебов можно создавать; полноценное редактирование вебов и удаление ещё не реализованы. Условия можно редактировать с историей. Нет реальной статистики и интеграции Buyo; у Scaleo есть проверка доступа чтения, запись ставок пока не реализована. Telegram поддерживает приём текста и ответы с черновиками после настройки. Live API, HTTPS-домен и работа с нескольких устройств ещё не проверялись. Задачи отображаются по московским календарным датам; фоновые уведомления пока отсутствуют. Сессия действует сутки. Ограничитель входа действует в пределах одного процесса и сбрасывается при его перезапуске.


## Telegram: подключение своего бота

1. Создайте бота у официального @BotFather командой /newbot, username должен заканчиваться на bot. Никому не отправляйте токен.
2. Запустите сайт через `npm run dev`, войдите и откройте «Подключения».
3. В блоке Telegram введите токен. Он передаётся только backend для проверки getMe и getWebhookInfo. В production требуется HTTPS; локально разрешён localhost. Токен не возвращается клиенту и сохраняется с AES-256-GCM.
4. Нажмите ссылку «Привязать мой Telegram», затем Start в Telegram. Ссылка одноразовая, действует 10 минут. До привязки обычный /start не вызывает ответа. После привязки принимаются только личные сообщения привязанного пользователя.
5. Перешлите текст договорённости. Бот выделяет явные поля и возвращает черновик. Без подключённого ИИ используется ограниченный парсер: распознаёт строки «Веб:», «Оффер:», «GEO:», «Гарантия:», «Дата: ГГГГ-ММ-ДД», упоминание одной компании и сумму с валютой. Неоднозначное нужно уточнить. Фото, аудио, «в понедельник» не интерпретируются автоматически.
6. Уточните последние условия командами /company Altex (или Buyo), /web имя или ID, /offer название, /geo KE, /rate 25 USD, /guarantee текст, /date ГГГГ-ММ-ДД. Для сохранения обязательны компания и веб. Остальные неопределённые поля остаются пустыми.
7. `/confirm НОМЕР` сохраняет условия и, если явно задана дата, задачу проверки запуска. `/cancel НОМЕР` отменяет черновик. Подтверждение не меняет ставки в партнёрке. Имя веба остаётся в условиях: автоматическая привязка или создание карточки пока отсутствует.
8. Обновите страницу сайта для просмотра записей. /help выводит справку.

Бот использует long polling: входящий публичный webhook не нужен. Нужен исходящий HTTPS-доступ к api.telegram.org. Не запускайте один токен на двух серверах одновременно. Не меняйте webhook чужого приложения: подключение такого бота будет отклонено. В «Подключениях» видны привязка, последняя ошибка; кнопка «Отключить» удаляет сохранённый токен и прекращает опрос.

Ключ шифрования хранится в `.data/secrets/telegram.key` (можно задать отдельную папку SECRET_DIR). Копируйте ключ отдельно от базы в защищённое хранилище; без него восстановленный токен не расшифровать. Не добавляйте ключ в Git. В compose для него выделен постоянный том telegram_secrets. При переносе с Mac на сервер сначала отключите бота на Mac и подключите его на сервере. Пока сервер работает только на Mac, бот зависит от его питания, сна и запущенного процесса. Плановые уведомления не реализованы.

Проверки Telegram выполнены с имитацией Telegram API: шифрование, привязка, запрет чужого аккаунта, парсер, отсутствие записи до подтверждения, повторное подтверждение без дублей, отмена и восстановление после перезапуска. Реальный бот пользователя без его локально настроенного токена не проверен.


## ИИ: обычные сообщения вместо заполнения полей

В «Подключениях» появился блок «ИИ · Разбор обычных сообщений». Выберите модель (по умолчанию gpt-4.1-mini), введите API-ключ OpenAI и подтвердите передачу присылаемых боту текстов провайдеру. Подписка ChatGPT не включает оплату API: нужен API-аккаунт с доступом к модели и отдельным биллингом. Проверка ключа читает доступ к выбранной модели, не делает платную генерацию. Первый разбор сообщения выполняет платный запрос. Ключ нельзя присылать в чат или записывать в обычные заметки.

Ключ хранится с AES-256-GCM с тем же защищённым ключом сервера, что Telegram. Нужен исходящий HTTPS к api.openai.com. Поле доступно после входа, только через HTTPS или localhost. При отключении AI сохранённый API-ключ удаляется, Telegram продолжает работать с явными полями.

После подключения просто перешлите обычную договорённость. В API передаются присланный текст и время исходного сообщения; при ответе на черновик — также его поля и исходный текст. Прочие карточки, контакты и переписки в API не отправляются. Текст обрабатывается как данные, модель не получает инструментов записи и доступа к сайту. JSON проверяется на сервере. Неясные факты остаются пустыми, а вопросы показываются в черновике. Относительная дата определяется по времени исходного сообщения в Москве, если модель может её однозначно установить; перед сохранением обязательно проверьте результат.

Для уточнения используйте в Telegram «Ответить» на сообщение бота с черновиком и напишите обычным текстом, например «это Buyo, веб Alex ID 28, запуск 2 ноября 2026». Затем ответьте на обновлённый черновик словом «подтверждаю» или отправьте `/confirm НОМЕР`. «отмена» ответом на черновик или `/cancel НОМЕР` отменяет его. Простое новое сообщение без ответа создаёт отдельный черновик. Если соглашений несколько, бот не сохраняет их одной записью и просит разделить. Создание/связывание карточки веба и сложные типы задач пока не автоматизированы.

При timeout, отказе модели, недоступном ключе, недостатке средств или некорректном JSON бот сообщает об ошибке. Разбор не подменяется простыми правилами и не сохраняет условия. Повторите сообщение после устранения причины; автоматических платных повторов нет. AI может ошибаться — сохранение остаётся за пользователем.

AI-протокол, валидация ответа, уточнения, подтверждение, отсутствие дублей, ошибки и отсутствие утечек ключа проверены на имитации API. Качество извлечения реальной моделью без настроенного ключа не проверялось. Фото, голосовые и несколько соглашений в одном сообщении пока не поддерживаются.


### Подробности оффера и AR

В AI-черновике и сохранённых условиях отдельно хранятся offerId, goalId, consumerPrice/consumerCurrency и ar/arMeaning. Выплата вебу и цена покупателя не смешиваются: «Ставка 28$» — 28 USD, «low price 2000 RSD» — цена покупателя 2000 RSD. GEO показывается с русским названием страны, например Сербия (RS), при сохранении исходного кода. Неизвестные коды не подменяются выдуманной страной.

Само «AR 27–30%» не считается гарантией. Бот просит уточнить, это ориентир, фактический показатель или согласованная гарантия, и до уточнения не сохраняет черновик. Ответьте на черновик обычным текстом при включённом ИИ. Старые черновики не переразбираются автоматически: отправьте исходное сообщение заново после обновления, а старый отмените. Регрессионная проверка PMT / MoveMAX / RS выполняется с имитацией ответа модели; качество live-извлечения проверяется пользователем локально.


### Уточнения после команды

Если нажать `/web` без значения, бот запрашивает имя/ID веба для конкретного открытого черновика; следующее короткое сообщение (например «103») меняет это поле, а не создаёт новый черновик. Аналогично работают /company, /offer, /geo, /rate, /guarantee, /date. Запрос хранится 10 минут и переживает перезапуск. `/cancel` без номера отменяет только запрос поля; `/cancel НОМЕР` отменяет черновик. При нескольких черновиках команда без ответа выбирает последний; команда ответом на черновик выбирает именно его.

Для смысла AR модель обязана дать точную цитату с явным указанием «ориентир», «фактический показатель» или «гарантия»; сервер проверяет наличие цитаты и соответствующего слова. Голый диапазон AR не проходит как доказательство смысла. Это консервативная проверка, она не заменяет подтверждение пользователем и может потребовать более явной формулировки. Для исходных сообщений формата «PMT ID 103» и «MoveMAX - RS (low price …)» добавлено восстановление явно заданных веба/оффера при пропуске полей моделью. Проверены пропуски и выдуманная классификация модели на имитации API; live-перепроверка остаётся на локальном боте пользователя.


Названия компаний нормализуются без учёта регистра и крайних пробелов: ALtex/ALTEX → Altex, BUYO → Buyo. Схема ответа ИИ ограничена Altex/Buyo/null. Неизвестная компания не отклоняет остальные поля: бот возвращает черновик и просит уточнение. При единственной отдельной строке Altex/Buyo в исходнике она восстанавливается, если модель пропустила компанию. Две компании без выбора требуют уточнения.


## Редактирование условий и история

В разделе «Условия» нажмите «Редактировать / история». Можно менять название, компанию, веба и его внешний ID, оффер и цель, GEO, выплату и валюту, цену покупателя, AR и его смысл, гарантию, дату, заметку и статус. Старые записи из Telegram открываются без ручного переноса: имя веба извлекается из заметки или названия. Новые подтверждения Telegram сохраняют web и externalAffiliateId отдельно.

Сохранение изменяет существующую запись, увеличивает её версию и атомарно записывает предыдущие/новые данные и компанию в историю. Если другая вкладка уже сохранила эту запись, вы получите конфликт вместо перезаписи: закройте редактор, обновите страницу и откройте запись снова. История доступна в редакторе. Запись и история переживают перезапуск. Изменение даты в условиях не переносит ранее созданную задачу. В текущем продукте один пользователь rama, поэтому изменения отмечаются этим пользователем.

Статусы «Проставлено вручную» и «Проверено вручную» — отметки пользователя о его действиях в кабинете, не результат работы интеграции. Редактирование и подтверждение Telegram сейчас не выполняют запись в Scaleo. Повторная отправка уже сохранённой договорённости создаёт новый черновик; автоматическое объединение с сохранёнными условиями пока отсутствует.

## Scaleo: проверка доступа

В «Подключениях» → «Altex · Scaleo» введите менеджерский API-ключ только на сайте и нажмите «Проверить доступ чтения». Нужен HTTPS или локальный localhost. Приложение использует фиксированный HTTPS-хост biosvet.scaletrk.com, ключ в query api-key (как требует проверенный API), таймаут 20 секунд, без переходов по redirect и без логирования URLs. Проверяется один GET /api/v2/network/affiliates с perPage=1, page=1. Проверка не является полной синхронизацией или проверкой прав записи. Сырые партнёрские ответы не сохраняются и не передаются в браузер; хранится только зашифрованный ключ и время проверки. Можно отключить подключение и удалить ключ.

Автоматическое проставление ставок не реализовано. Не подтверждён API-метод персональных выплат, его схема, чтение текущей ставки и права пользователя. В облачной среде запрос официальной документации https://developers.scaleo.io/ вернул HTTP 403; ключа Scaleo в ней нет. Не выполнялись пробные изменяющие запросы или live-проверки. Следующий этап после проверки чтения — подтверждение документации персональных ставок, предварительный просмотр конкретного изменения affiliate/offer/goal/валюта и сверка после записи. Нельзя считать локальный статус доказательством изменения в партнёрке.

Ответ на черновик «Ожидаемый» теперь напрямую уточняет AR как ориентир, сохраняя остальные поля и не вызывая повторно ИИ. Поддержаны также «Ориентир», «Фактический показатель», «Гарантия». Схема ответа модели ограничивает смысл AR допустимыми значениями; неизвестный смысл приводит к вопросу, не к потере черновика. Автотесты используют имитации внешних API; реальные ключи остаются у пользователя на Mac.
