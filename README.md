# Rama — рабочий помощник

Первая основа закрытого сайта для Altex и Buyo. Есть вход, общая база вебов, задачи с завершением, записи условий, черновики контента и отдельный раздел подключений. Интерфейс адаптирован для телефона. Это версия для разработки, ещё не размещённый публичный сайт.

## Запуск на Mac

1. Установите Node.js 24 LTS.
2. Откройте папку проекта в терминале.
3. Выполните `npm ci`.
4. Скопируйте `.env.example` в `.env` командой `cp .env.example .env`.
5. В `.env` задайте свой `ADMIN_PASSWORD` (минимум 12 символов). Не отправляйте пароль в чат и не добавляйте `.env` в Git.
6. Выполните `npm run dev`. Откройте локальный адрес с портом 3000 в браузере и войдите с указанным паролем.

При первом запуске создаётся единственный пользователь rama. Публичной регистрации нет. Пароль из .env применяется только при первоначальном создании пользователя; его изменение в файле не меняет уже сохранённый пароль.

## База и проверки

Без DATABASE_URL используется PGlite — встроенный PostgreSQL-движок, сохраняющий данные в `.data/postgres`. Он подходит для одной локальной копии приложения. Не запускайте несколько экземпляров на одной папке данных.

`npm test` проверяет вход, защиту Origin, запрет доступа без сессии, разделение компаний, создание и завершение задач, восстановление базы и сессии после перезапуска, выход. `npm run build` собирает интерфейс.

Для внешнего PostgreSQL задайте DATABASE_URL. Схема создаётся при старте. В проекте нет демонстрационных записей. Интерфейс сохраняет данные только через сервер.

## Интеграции

В «Подключениях» есть Altex и Buyo и возможность добавить описание источника. Сейчас это реестр источников: адаптеры, проверка API, синхронизация и ввод ключей ещё не реализованы. Нельзя вводить секреты в название или заметку. Статистика честно показывает отсутствие подключения. Подключения будут добавляться отдельно после создания основы сайта, без ключей в коде frontend.

## Размещение с PostgreSQL

Выберите хостинг и домен. Платные ресурсы не создавались. Подготовлены Dockerfile и compose.yaml; Docker-сборка и внешний PostgreSQL в этой среде пока не проверялись.

В защищённых настройках хостинга задайте ADMIN_PASSWORD и POSTGRES_PASSWORD (для compose используйте разные стойкие буквенно-цифровые пароли). Запустите `docker compose up -d --build`. Поставьте HTTPS reverse proxy перед локальным портом 3000; не публикуйте PostgreSQL. В production cookie требует HTTPS, поэтому вход через обычный HTTP не будет работать. Приложение доверяет одному reverse proxy: не предоставляйте прямой внешний доступ к его порту. Проверка состояния: GET /api/health, без выдачи рабочих данных.

Контейнер app работает без root. База хранится в томе postgres_data. Не используйте `docker compose down -v`: это удаляет базу. Сайт на хостинге не зависит от включённого Mac, но фактическое размещение ещё не выполнено.

## Резервные копии

Для локальной версии остановите приложение, скопируйте целиком `.data/postgres` в защищённое место, затем запустите приложение. Для восстановления остановите приложение и замените папку данных копией. Копия содержит рабочие данные и хеш пароля — храните её закрытой.

Для compose: `docker compose exec -T db pg_dump -U rama -d rama > backup.sql`. Настройте ежедневные копии средствами хостинга, шифрование и ограниченный доступ. Восстановление в пустую подготовленную БД: `docker compose exec -T db psql -U rama -d rama < backup.sql`. Команды контейнерного восстановления пока не проверялись в этой среде.

## Ограничения первой версии

Условия и контент пока сохраняются как записи: нет истории изменений условий, публикации и планировщика. Карточки можно создавать; полноценное редактирование и удаление ещё не реализованы. Нет реальной статистики и интеграций Scaleo/Buyo. Telegram поддерживает приём текста и ответы с черновиками после настройки. Live API, HTTPS-домен и работа с нескольких устройств ещё не проверялись. Задачи отображаются по московским календарным датам; фоновые уведомления пока отсутствуют. Сессия действует сутки. Ограничитель входа действует в пределах одного процесса и сбрасывается при его перезапуске.


## Telegram: подключение своего бота

1. Создайте бота у официального @BotFather командой /newbot, username должен заканчиваться на bot. Никому не отправляйте токен.
2. Запустите сайт через `npm run dev`, войдите и откройте «Подключения».
3. В блоке Telegram введите токен. Он передаётся только backend для проверки getMe и getWebhookInfo. В production требуется HTTPS; локально разрешён localhost. Токен не возвращается клиенту и сохраняется с AES-256-GCM.
4. Нажмите ссылку «Привязать мой Telegram», затем Start в Telegram. Ссылка одноразовая, действует 10 минут. До привязки обычный /start не вызывает ответа. После привязки принимаются только личные сообщения привязанного пользователя.
5. Перешлите текст договорённости. Бот выделяет явные поля и возвращает черновик. Это ограниченный парсер без AI: распознаёт строки «Веб:», «Оффер:», «GEO:», «Гарантия:», «Дата: ГГГГ-ММ-ДД», упоминание одной компании и сумму с валютой. Неоднозначное нужно уточнить. Фото, аудио, «в понедельник» не интерпретируются автоматически.
6. Уточните последние условия командами /company Altex (или Buyo), /web имя или ID, /offer название, /geo KE, /rate 25 USD, /guarantee текст, /date ГГГГ-ММ-ДД. Для сохранения обязательны компания и веб. Остальные неопределённые поля остаются пустыми.
7. `/confirm НОМЕР` сохраняет условия и, если явно задана дата, задачу проверки запуска. `/cancel НОМЕР` отменяет черновик. Подтверждение не меняет ставки в партнёрке. Имя веба остаётся в условиях: автоматическая привязка или создание карточки пока отсутствует.
8. Обновите страницу сайта для просмотра записей. /help выводит справку.

Бот использует long polling: входящий публичный webhook не нужен. Нужен исходящий HTTPS-доступ к api.telegram.org. Не запускайте один токен на двух серверах одновременно. Не меняйте webhook чужого приложения: подключение такого бота будет отклонено. В «Подключениях» видны привязка, последняя ошибка; кнопка «Отключить» удаляет сохранённый токен и прекращает опрос.

Ключ шифрования хранится в `.data/secrets/telegram.key` (можно задать отдельную папку SECRET_DIR). Копируйте ключ отдельно от базы в защищённое хранилище; без него восстановленный токен не расшифровать. Не добавляйте ключ в Git. В compose для него выделен постоянный том telegram_secrets. При переносе с Mac на сервер сначала отключите бота на Mac и подключите его на сервере. Пока сервер работает только на Mac, бот зависит от его питания, сна и запущенного процесса. Плановые уведомления не реализованы.

Проверки Telegram выполнены с имитацией Telegram API: шифрование, привязка, запрет чужого аккаунта, парсер, отсутствие записи до подтверждения, повторное подтверждение без дублей, отмена и восстановление после перезапуска. Реальный бот пользователя без его локально настроенного токена не проверен.
